Skua can't write to its data directory

The container runs as a non-root user with uid/gid 65532, but the data directory isn't writable by it. Skua needs to store the camera list, your preferences, and group settings there, so it can't start until this is fixed.

Path

{{.Detail}}

Fix with one of

chown -R 65532:65532 {{.Detail}}
or

Switch to a named Docker volume in your compose file. Docker manages permissions for named volumes automatically, so there's nothing to chown.

Then restart the container

docker compose restart skua
{{else}}

Skua can't reach Frigate

On first start Skua reads the camera list from Frigate's API. There's no cached snapshot on disk yet, so it can't continue until Frigate responds.

Configured target

{{.Detail}}

Check that

Frigate is running, and FRIGATE_URL points at Frigate's internal API on port 5000. Not the authed UI on 8971, and remapped if your compose file moved it.

Then restart the container

docker compose restart skua
{{end}}
